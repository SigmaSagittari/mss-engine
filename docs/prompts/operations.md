# 工具与执行 Prompt

范围：只适用于 `code/`。

前置：必读清单见 `AGENTS.md`（`../../AGENTS.md`），规则归属见 `docs/README.md`（`../README.md`）。

## 构建与 correctness 测试

### 构建入口

| 环境 | 入口 |
| --- | --- |
| MinGW | 仓库根目录的 `build.bat` |
| Visual Studio | 仓库根目录 `vs/` 下的解决方案文件 |

- 不要自行新建构建系统，也不要改工程路径。

### 工具环境

- 现有工具环境是 `D:/codeenvset`。
- 按仓库脚本使用它：不要自行换路径，也不要改系统级安装。

### 临时目录

- 临时构建、测试和性能实验，都放在 Git 仓库之外的专用目录。
- 进程的工作目录要显式设成该目录。
- 临时驱动、源码快照、目标文件、可执行文件和日志，从创建起就写入该目录，不要先落在仓库里再移动。
- 目的是让仓库的变更列表只含任务的源码、工程和文档修改。

### 运行 correctness 测试

- 实现、修复或测试任务中，correctness 测试可以直接运行，不需要逐次申请。
- 但运行前要确认它不会修改源码或用户数据。
- 运行后报告四项实际值：实际命令、实际耗时、退出状态、实际输出。

### 硬超时

- 任何运行都要设一个有限的外部硬超时。理由是防止死循环、失控内存或长期占用机器。
- 超时要略大于预估的正常工作时间，不能等于或小于。

## benchmark

### 什么时候跑

- 适用范围：`ui/` 以外的代码。
- 是否跑由用户判断：
  - 小修小补，不跑；
  - 只有大修大补（例如重写搜索树）才值得跑。
- 跑之前先说明三件事：改动规模、要验证的指标、预计耗时。得到用户同意后再跑。

### 怎么跑

- 交付前最多跑一次，一次跑完。
- 结果异常时先报告，等用户决定，不要自行重跑。
- benchmark 必须设外部硬超时。

### 记录什么

每次 benchmark 记录：

- 输入尺寸；
- 种子或固定盘面；
- 目标时长；
- 实测耗时；
- 样本数 / 对局数；
- 吞吐量。

没有测量到的数字，明确标为假设或未验证。

## 下载与代理

- 下载失败时，按用户给出的环境要求尝试代理。
- 不要把代理、凭据或大文件下载过程写进源码。
- 如果需要输入凭据，或者需要明显超出当前任务的下载，先向用户说明。
