# 代码风格

本文件管 `code/` 的 C++ 写法、类型组织和文件接口形式。

- 必读清单、授权与适用范围：见 `AGENTS.md`（`../../AGENTS.md`）
- 规则归属：见 `docs/README.md`（`../README.md`）
- 实现中的可靠性、性能和 UI 职责边界：见 `implementation.md`

## C++ 语法与格式

以下约定适用于本次新增和修改的 C++ 行，审查者逐项检查 diff。

### 类型转换

- 禁止 `static_cast`。显式转换只在确有必要时使用，写法是 C 风格 `(typename) value`。
- 只有能从数学上证明会影响计算结果时，才添加显式转换。
- 唯一例外：为消除 MinGW `-Wall` 的符号比较告警，比较表达式里允许把 `size_t` 转成 `int`。

### 循环

- `for` 循环必须显式写出循环变量类型。正向和反向按对应上下文写：

  ```cpp
  for (int i = 0; i < (int)XX.size(); ++i)        // 正向
  for (int i = (int)XX.size() - 1; i >= 0; --i)   // 反向
  ```

- 禁止 `auto`。只有两种情形可以用：
  - 结构化绑定，例如 `auto [x, y] = value`；
  - lambda 变量，例如 `auto function = lambda`。
- 范围 for 仍然要显式声明元素类型。

### 格式与分支

- 不得把单行代码随意拆成多行。
- 禁止 C++ `switch`，用项目现有的 `if/else` 风格。

### 作用域与组织

- 禁止匿名 namespace。
- 禁止文件或命名空间作用域的 `static` 函数、变量。
- 函数内 `static` 只允许两类：只读常量表；下文 Workspace 一节规定的 `thread_local` 工作区。
- 模块内部实现通过所属类型组织。

### 注释

- 注释必须用中文。
- 不要写这三种注释：没有代码依据的、只复述代码的、推测未来设计的。

### 风格一致性

- 命名、空格、括号、类型、include 顺序、函数布局，严格贴合相邻实现。

### 标准库设施

- 本库不使用 `std::optional`、`std::span` 等设施。
- 需要可选状态、视图或范围时，用项目自己的类型和显式契约（指针+长度、ID、`Result` 等）。
- 确有必要时，先说明三件事——数据布局、生命周期、运行成本——取得用户明确同意后再用。

### 所有权转移

- 禁止 `std::move`。
- 需要转移存储所有权时，直接移交指针及对应的长度、容量，并清空原所有者。
- 不得为此添加移动构造、移动赋值或转发包装。

`explicit`

- 禁止使用 `explicit`，包括构造函数和转换函数。

### 成员函数

- 函数只定义为非 `static` 成员函数，调用规格是：
  1. 优先通过现有对象调用；
  2. 其次构造空壳对象调用。
- 没有第三级。`static` 成员函数一律不用。
- 类的 `static` 数据成员只允许只读常量表；需要可变状态，放 `Pool` 或 `Workspace`，按它们的契约。

## 结构体与初始化

### 初始值写在哪

禁止在 `struct` / `class` 的字段声明处写默认成员初始化，例如 `int count = 0;`、`bool enabled = false;`、`Value value{};`。

合理的固定初始状态，必须在构造函数的初始化列表里明确建立，例如 `vector`（`code/core/datastructure/vector.h`）：

```cpp
vector() : data(nullptr), size(0), capacity(0) {}
```

### 保存实际数据的结构体是纯粹的存储类型

逐字段沿实际构造、写入和读取路径判断它属于哪一类。

第一类：不存在合理的默认值，且延迟构造没有性能损失

- 写法：先完成计算或组装，再通过构造参数提供完整实际值。
- 例：`ObservedBoard::Result`（`code/algo/probability_engine/observed_board/observed_board.h`）在构造时写入实际雷数和全 `Hidden` 盘面。

第二类：不存在合理的默认值，且延迟构造会造成性能损失

- 只适用于确属预分配、复用或批量填充的存储槽，不是通用的免初始化许可。
- 写法：实际数据字段不初始化，保留给后续直接写入。
- 必须用中文注释写明「危险」，并说明三件事：性能原因、有效范围或占用状态、首次写入位置。
- 必须保证所有读取和累加之前已有实际赋值。
- 涉及复制或搬移时，不得读取未写入字段。
- 未写入且没有用途的字段，应当删除。
- 例：`FlatHashTable::Slot`（`code/core/datastructure/flat_hashtable.h`）的 key/value 只在 `used` 置位后才读；`vector::resize`（`code/core/datastructure/vector.h`）增大的区域不初始化。

第三类：存在合理的默认值

- 写法：由类型自身在构造函数初始化列表中建立，调用方无需显式提供。
- 例：空容器对应的计数 0、`vector` 的空状态、`Grid`（`code/core/datastructure/grid.h`）的零行零列、搜索节点数从 0 开始、共享缓存初始关闭。

### 占位值

禁止用 `-1`、0、空对象等占位值，代替本应提供的真实值。

刻意设计的「未计算」「不存在」这类业务状态属于第三类，但必须做到两点：沿实际调用核实其含义；用中文注释说明。

## 算法模块的五类职责

算法模块按五类职责组织：算法本体、结果与增量（`Result` / `Delta`）、`Pool`、`Workspace`、`Config`。按实际需要定义对应类型。

### 算法本体

- 一个外层类型组织模块 API、内层类型、类型别名和枚举，通过成员函数提供算法入口。
- 外层类型自身是空壳：不持有数据、缓存、配置或工作内存，也不在它上面再叠第二层 facade。
- 模块自己的结果、增量、池、工作区、配置，都归属于本模块的外层类型。跨后端共享类型的定义与公开方式见下文「文件组织与依赖方向」。
- `Config` 与 `Workspace` 均归属于对应模块：`Config` 提供公开参数；`Workspace` 及其内部附属类型定义放在所属 `.cpp`。两者互不嵌套，也不互为存储位置。
- 配置依赖自上而下组合：上层模块的 `Config` 可以包含下层对应类型；下层头文件不得包含上层聚合器。层级越低，只看到自己需要的部分。
- 模块 API 只接收自己需要的 `Module::Config`（`const &`），不接收整棵上层聚合。工作区取用见下文 Workspace 一节。
- 主 `mss::Config` 只承接入口模块的配置类型；入口模块再组合需要的下层配置。主聚合器只组合类型，不重定义模块字段。

### Result / Delta

- `Result` 保存计算结果，`Delta` 保存增量变化。
- 两者的数据供生成它的函数返回后使用；依赖池的部分，由相应 `Pool` 覆盖其有效期。
- `Result` 不得再保存一份已有对象已经持有的相同状态。
- `Delta` 只用于算法天然支持增量更新、且能正确逆序撤回的场景。两个条件要同时成立。
- 结果中的 ID、引用、指针/长度和切片，必须注明所属池，以及池写入或清空后何时失效。API 契约要能看清所有者和有效期。

### Pool

- `Pool` 保存跨函数调用使用的存储，生命周期覆盖依赖它的数据。
- `Pool` 只在确需 intern / 共享存储、稳定 ID，或引用需要跨调用复用时才存在。
- 禁止隐式共享：不得通过 `Pool` 成员在函数之间隐式传递数据。要传数据，调用方必须把成员引用作为显式参数传入。
- `Pool` 本身不作为返回值、结果对象或隐式参数包。
- 分段存储的组织、读写和回退规则见下文「vectorPool 的使用」。

### Workspace

八条，各自独立。

1. 用途与内存

- 模块通过普通成员函数 `getWorkspace()` 取得内部的 `Workspace&`。
- 函数内以 `static thread_local Workspace` 持有并复用临时容器及已分配内存，避免重复申请和释放。
- getter 定义使用 `__declspec(noinline)`：把 TLS 寻址和初始化检查留在 getter 里，算法入口取得引用后使用普通地址。
- 公开算法接口省去工作区参数。完整工作区及内部辅助数据类型定义留在 `.cpp`；头文件保留必要的前置声明、getter 和算法函数声明。
- 函数体内不得新建 STL 容器，也不得用自定义 `vector` 或局部结构体绕过。
- 跨调用保留的结果、缓存和状态，由对应的结果、池或状态对象持有，不要放进工作区。

2. 职责

- Workspace 及其存储子类型只持有临时存储，并提供必要的初始化、清理、扩容及存储查询操作。
- 搜索、推导、评分、候选筛选和 DP 推进，归所属算法类型，遵循普通成员函数优先的约定。
- 算法所需的私有声明可以留在所属算法类型的头文件中。
- 禁止为了隐藏这些声明，把计算函数放进 Workspace。

3. 调用与引用

- 每个文件由所属算法类型持有一个大的工作区，临时存储按用途嵌套组织。
- 每个需要临时存储的函数，自行调用本文件的 `getWorkspace()` 取得引用，再访问自己的嵌套存储；函数之间省去整个 Workspace 及子工作区参数。
- 使用工作区容器时，必须显式写出具体容器类型并绑定局部引用：

  ```cpp
  vector<int> &items = workspace.items;
  vector<int> &suffixStart = workspace.sample.suffixStart;   // 嵌套容器同样直接绑定到具体容器
  ```

- 禁止给整个工作区建立引用别名再通过别名访问成员，例如 `Workspace &ws = workspace;`。
- 实际输入、中间计算结果和输出，继续通过显式参数传递。
- 传递容器引用时，收到 `vector&` 后按接口读写。

4. 禁止隐式共享

- 禁止通过 `Workspace` 成员在函数之间隐式传递数据。要传数据，调用方必须把成员引用作为显式参数传入。
- `Workspace` 本身不作为计算结果或隐式参数包。

5. 生命周期

- 分配的内存可以留在 `Workspace` 中复用；数据只在当前最外层调用链内有效，链结束后失效。
- 不得依赖前次调用的数据。
- 不得把当前调用的成员、引用、指针或切片带出该调用链，也不要存进更长寿命的对象、或作为后续独立调用的输入。
- 禁止用 `swap` / `swapStorage` 转交工作区容器的存储。

6. 脏数据与初始化

- 旧内容默认视为脏数据，可以在本次使用前清理，也可以在上次返回前清理。
- 空/零状态必须由构造和所有返回路径（含提前返回）维护。
- 没有清理保证的区域，下次使用前覆盖或重置。
- 函数负责建立有效范围和初态；完全覆盖写入的无需清零。

7. 容器与 STL

- 除 `mss::vector` 外，使用其他 STL 须事先申报四件事——位置、用途、分配成本、生命周期——并获明确同意。
- 批准的含义是允许该类型进入 Workspace，不是允许它进函数体。上文第 1 条的禁令对获批类型同样成立：函数体内不得新建任何 STL 数据结构。
- 批准只适用于获批用途。

8. 正确性与并发

- 遵守清理约定时，相同显式输入的结果，必须与工作区复用历史无关。
- getter 在当前执行线程取用工作区。
- Position、Game 及任务对象不保存工作区引用。
- 线程间交接任务后，各算法在执行线程取得该线程的工作区。
- 同线程的多个局面串行复用。
- 嵌套调用时，沿实际调用关系确认工作区是否共享。

### Config

`Config` 只保存调用方需要调整的参数，每项都必须在构造时明确提供。类型本身不设固定默认值或默认实参。

固定算法规则、版本号等程序信息，放在实现或独立常量中。

- 配置作为只读参数传入。
- 只有确实要协调多个模块参数的上层边界，才接收完整的上层 `Config`。
- 只想用一个阈值时，传具体值或该模块的配置。

## 嵌套类型与字段分类

- 尽可能减少在一个结构体里堆放过多内容。
- 字段较多、或存在清晰的职责分组时，积极用嵌套类型分类；子组内仍有不同职责时，继续嵌套。
- 类型和字段按直接所属的模块、阶段或数据集合归组，通过嵌套路径表达归属。
- 拆分以实际职责为依据。

## vectorPool 的使用

`vectorPool<T>` 用一个连续的 `mss::vector<T>` 存放多段同类型元素；`vectorPool<T>::vector` 只保存一段的 offset/count。

它的用途主要分四类：

| 用途 | 组织方式 | 示例 |
| --- | --- | --- |
| 对象的变长内容 | 对象保存各段切片，实际内容按元素类型集中存储；多个对象可以共享所属池。 | `Structure::Shape` / `Instance`、`ShapeSolver` 的分布与赋值、模板匹配表。 |
| 增量记录 | 每次更新追加一段变化，`Delta` 或评分结果保存该段，供后续重放、逆序撤回或继续搜索。 | `ObservedBoard` / `Basic` / `Structure` 的变化记录、`JavaLite` 的数字结局记录。 |
| 树的子节点列表 | 节点本体集中存储，每个节点用同一池中的切片表示一组连续子节点；根列表也用切片表示。 | `AnytimeSearch::Pool::Node::child` 与 `Result::roots`。 |
| 临时分组与计算缓冲 | 一次调用或递归帧内拼接多组数据、系数或中间表，记录切片以便独立访问各段；下次使用时重建内容并复用容量。 | 暴力求解的安全组、`PolyProductTree` 的系数、概率抽样的后缀多项式、DFS 观测的卷积缓冲。 |

### 存储归属

按数据有效期选择持有者：

- 跨调用共享的内容，放在对应 `Pool`；
- 结果独占的分段内容，可以由结果自身持有，例如 `ShapeSolverType::Observed::values`；
- 临时段放在 `Workspace` 或其递归层内，并遵守上文的工作区契约。

### 分段布局

- 多个同类型变长数据段共用生命周期时，优先用 `vectorPool<T>` 存元素，由所属对象保存切片。
- 单独组织切片列表时，用 `vector<vectorPool<T>::vector>`。
- 不要只为保持地址稳定就逐段分配、再用 `vector<T *>` 管理。
- 复杂对象的同类型变长成员可以分别入池，对象保存对应切片。
- 池内元素须满足 `mss::vector<T>` 的可平凡复制约束。

### 追加与填充

- `push_back()` 在池尾建立空切片；`push_back(part, value)` 只向当前尾部切片追加。
- 建立后续段之前，先完成当前段的长度分配。
- 已知各段长度时，可以先分配各段，再按下标填充；已分配的段可以在有效范围内改写。
- 直接用 `data.resize()` 划分缓冲时，同步建立正确的 offset/count；初始化规则见上文「结构体与初始化」。

### 切片与指针

- 切片必须配合所属池读取。
- 池扩容不改 offset/count，但会使旧的元素指针、引用及基于它们的视图失效。
- 跨追加操作要保留切片或下标，追加完成后再从池中取得所需地址。
- 把某个段转存到另一个池时，复制实际元素，并在目标池建立切片。
- 段内另存的 begin/offset，要注明是相对本段还是整个池。

### 回退与清空

- `pop_back(part)` 把池长度退到 `part.offset`，截断该段及其后的内容。
- 它只回退存储，状态撤回由算法完成。
- 增量记录在撤回消费完之后再退池；去重命中时可以丢弃本次新建的尾段。
- 只保留仍然有效的切片；池清空或销毁后，不再使用旧切片。

## 文件组织与依赖方向

### 基本要求

- 新增或修改必须服从 `code` 的既有文件组织。
- 对本来以头文件组织的模块，按相邻模块的风格做最小改动。

### 多后端的组织顺序

一个统一入口下有多个算法后端时，按下面的顺序组织：

```
XXX_type.h → (XXX_algoA.h / XXX_algoB.h) → XXX.h
```

- 共享类型定义在 `XXX_type.h`；
- 后端包含共享定义，并直接使用同一种结果类型；
- 对外入口 `XXX.h` 汇总后端、公开类型，并提供统一调用入口。
- 公共配置可以独立放在 `XXX_config.h`，供实际需要的层直接包含。

### 箭头方向

- 箭头表示从共享定义、后端到对外入口的组织顺序。
- include 依赖方向：入口 → 后端 → 共享定义。
- 后端不反向包含对外入口；共享定义不依赖后端。
- 入口可以用 `using` 公开共享类型。

### 同名头/源文件模式

- 头文件放公开类型、契约和声明；非模板实现放同名 `.cpp`。
- 模板定义、以及确实必须在头文件里的实现，留在头文件。
- `.cpp` 先包含自己的头文件，再包含实现依赖。

### API 注释

- 写清可执行的前置条件、对象所有权、引用或视图有效期、并发限制。
- 每条约束要能从实现核实。
