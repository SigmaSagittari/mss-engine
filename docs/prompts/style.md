# 代码风格（mss0.16）

本文件适用于 `code/` 的 C++ 写法、类型组织和文件接口形式。必读清单、授权与适用范围见 [AGENTS.md](../../AGENTS.md)，规则归属见 [docs/README.md](../README.md)。实现中的可靠性、性能和 UI 职责边界见 [implementation.md](implementation.md)。

## C++ 语法与格式

以下约定适用于本次新增和修改的 C++ 行。审查者逐项检查 diff；例子不是唯一允许的写法。

1. 禁止 `static_cast`。只有确有必要的显式转换才使用 C 风格 `(typename) value`；能隐式转换时不额外添加显式转换。为消除 MinGW `-Wall` 符号比较告警，仅在比较表达式中允许将 `size_t` 转为 `int`。
2. `for` 循环必须显式声明循环变量类型。正向和反向遍历都按对应上下文写：
   - `for (int i = 0; i < (int)XX.size(); ++i)`
   - `for (int i = (int)XX.size() - 1; i >= 0; --i)`
3. 禁止 `auto`，仅允许两种情形：结构化绑定，例如 `auto [x, y] = value`；lambda 变量，例如 `auto function = lambda`。范围 for 仍然显式声明元素类型。
4. 不得把单行代码随意拆成多行。单行语句、条件和调用都保持单行；不要为了视觉对齐、参数换行或“更易读”改成多行。
5. 禁止 C++ `switch`，使用项目现有的 `if/else` 风格。
6. 禁止匿名 namespace 和文件内 `static` 局部变量；不把单个源文件视为特殊单元。不要以单文件私有缓存、隐式全局状态或只在某个编译单元成立的假设绕开模块接口。
7. 注释必须使用中文。不要添加没有代码依据、只是复述代码或推测未来设计的注释。
8. 命名、空格、括号、类型、include 顺序和函数布局严格贴合相邻实现。不要顺手重排旧代码。
9. `mss0.16` 不使用 `std::optional`、`std::span` 等设施。需要可选状态、视图或范围时，用项目自己的类型和显式契约（指针+长度、ID、`Result` 等）。确有必要时，先说明数据布局、生命周期和运行成本，取得用户明确同意后再用。
10. 禁止使用 `std::move`。需要转移存储所有权时，直接移交指针及对应长度、容量，并清空原所有者；不得为此添加移动构造、移动赋值或转发包装。
11. 禁止使用 `explicit`，包括构造函数和转换函数。

交付前逐行检查本次 C++ diff：

- 搜索 `static_cast`，确认新增或改动的代码行中没有它。
- 搜索 `std::move`，确认新增或改动的代码行中没有它；检查所有权移交后的原指针、长度、容量均已清空，没有重复释放或继续使用原存储。
- 搜索 `explicit`，确认新增或改动的代码行中没有它。
- 搜索 `switch`、匿名 namespace、文件内 `static` 局部变量和所有 `auto`；只允许上面列出的两种 `auto`。
- 逐个检查正向与反向 `for`，循环变量必须显式写类型；倒序时不得把 `size() - 1` 写成未转换的无符号减法或漏掉正确的空长度起点。
- 检查单行语句是否被排版拆开，及新增注释是否为中文。
- 检查新增代码没有引入 `std::optional`/`std::span`；如有，必须有用户批准和理由。

## 结构体与初始化

禁止在 `struct` / `class` 的字段声明处写默认成员初始化，例如 `int count = 0;`、`bool enabled = false;`、`Value value{};`。合理的固定初始状态必须在构造函数的初始化列表中明确建立，例如 [vector](../../code/core/datastructure/vector.h) 的 `vector() : data(nullptr), size(0), capacity(0) {}`；这不授权给其他字段补占位值，也不要求调用方传入固定初值。

保存实际数据的结构体应是纯粹的存储类型。逐字段沿实际构造、写入和读取路径区分以下三类，不能仅凭类型名或默认值的数值决定：

1. 不存在合理的默认值，且延迟构造没有性能损失：先完成计算或组装，再通过构造参数提供完整实际值；创建后立即赋实际值的记录也直接改为带参构造。不得把占位值机械搬到调用处。例如 [ObservedBoard::Result](../../code/algo/probability_engine/observed_board/observed_board.h) 在构造时写入实际雷数和全 `Hidden` 盘面。
2. 不存在合理的默认值，且延迟构造会造成性能损失：确属预分配、复用或批量填充的存储槽时，实际数据字段不初始化，保留后续直接写入；必须用中文注释写明“危险”，说明性能原因、有效范围或占用状态、首次写入位置，并保证所有读取和累加之前已有实际赋值。涉及复制或搬移时不得读取未写入字段。例如 [FlatHashTable::Slot](../../code/core/datastructure/flat_hashtable.h) 的 key/value 只在 `used` 置位后读取；[vector::resize](../../code/core/datastructure/vector.h) 增大的区域不初始化。不能仅以“工作区”或“稍后会赋值”为名套用例外。未写入且没有用途的字段应删除；不存在合法写入路径却会被读取的字段是 Bug，不能补默认值掩盖。
3. 存在合理的默认值：由类型自身在构造函数初始化列表中建立，调用方无需显式提供，不把固定初值作为构造参数。例如空容器对应的计数 0、[vector](../../code/core/datastructure/vector.h) 的空状态、[Grid](../../code/core/datastructure/grid.h) 的零行零列、搜索节点数从 0 开始、共享缓存初始关闭。

- 禁止用 `-1`、0、空对象等默认值代替应当提供的真实值，再靠后续回退掩盖遗漏。刻意设计的“未计算”“不存在”等业务状态属于第三类，但必须沿实际调用核实其含义，并用中文注释说明；不能用一个哨兵值把不完整的数据记录伪装成合法状态。
- 延迟写入只适用于已核实的存储契约，不能作为普通数据记录漏赋值的通用豁免；涉及复制或搬移时也要检查未写入字段是否会被读取。
- 固定初值不代替跨调用复用时所需的重置；复制会保留已有状态，复制一个带计数的状态或工作对象后，仍须清零自己的计数。
- 这非常复杂，写的时候需要重点关照，目的是绝对避免占位值以任何方式流入计算。

## 算法模块的五类结构

算法模块按以下五类职责组织；按实际需要定义对应类型。

### 算法本体

- 一个外层类型组织模块 API、内层类型、类型别名和枚举，通过静态函数提供算法入口。外层类型自身为空壳，不持有数据、缓存、配置或工作内存，不再叠第二层 facade。
- 模块自己的结果、增量、池、工作区和配置归属于本模块外层类型。跨后端共享类型的定义与公开方式见下文「文件组织与依赖方向」。
- `Config` 与 `Workspace` 在模块归属、类型层级和主聚合位置上地位相同、彼此独立，位于模块下同级内层；两者互不嵌套，也不互作存储位置。
- 依赖树自上而下组合：上层模块的 `Config`/`Workspace` 可以包含下层对应类型；下层头文件不得包含上层聚合器。层级越低，只看到自己需要的部分。
- 模块 API 只接收自己需要的 `Module::Config`（`const &`）和/或 `Module::Workspace`（`&`），不接收整棵上层聚合。上层调用下层时，取出对应的子配置或子工作区传入。
- 主 `mss::Config` / `mss::Workspace` 只承接入口模块的对应类型，入口模块再组合需要的下层模块；主聚合器只组合类型，不重定义模块字段或缓存。

### Result / Delta

- `Result` 保存计算结果，`Delta` 保存增量变化；其数据供生成它的函数返回后使用，依赖池的部分由相应 `Pool` 覆盖其有效期。
- `Result` 不得再保存一份已有对象已经持有的相同状态。
- `Delta` 只用于算法天然支持增量更新、且能正确逆序撤回的场景；做不到就不定义，不为了“长得像概率增量”造一个假的。
- 结果中的 ID、引用、指针/长度和切片必须注明所属池，以及池写入或清空后何时失效。API 契约要能看清所有者和有效期。

### Pool

- `Pool` 保存跨函数调用使用的存储，其生命周期覆盖依赖它的数据；只在确需 intern/共享存储、稳定 ID 或引用跨调用复用时存在。
- 分段存储的组织、读写和回退规则见下文「vectorPool 的使用」。

### Workspace

- 用途与内存： 调用方持有 `Workspace`；它持有并复用临时容器及已分配内存，避免重复申请和释放。函数体内不得新建 STL 容器，也不得用自定义 `vector` 或局部结构体绕过。跨调用保留的结果、缓存和状态由对应的结果、池或状态对象持
- 调用与引用： 模块函数可按接口接收本模块的 `Workspace&` 作为临时内存。使用工作区容器时，必须显式写出具体容器类型并绑定局部引用，例如 `vector<int> &items = workspace.items;`；嵌套容器同样直接绑定到具体容器，例如 `vector<int> &suffixStart = workspace.sample.suffixStart;`。禁止给整个工作区建立 `Workspace &ws = workspace;` 等引用别名，再通过别名访问成员。子模块的工作区可按接口直接传入下层函数。数据可沿当前调用链由上层逐层通过显式引用参数传给下层；只需要单个成员的辅助函数就接收该成员引用。收到 `vector&` 后按接口读写，不判断它来自普通 `vector` 还是 `Workspace`。
- 禁止隐式共享： 禁止通过 `Workspace` 成员在函数之间隐式传递数据：一个函数写入成员后，另一个函数不得只凭再次收到同一个 `Workspace` 参数就读取该成员。要传递数据，调用方必须把成员引用作为显式参数传入；这种约束只针对 `Workspace`，不限制普通对象作为函数参数传递。`Workspace` 本身不作为返回值、结果对象或隐式参数包；要在调用链中传递结果，用结果对象或调用方显式传入的引用，这是为了避免另类的全局变量。
- 生命周期： 分配内存可留在 `Workspace` 中复用，数据只在当前最外层调用链有效，链结束后失效；不得依赖前次调用的数据。不得把当前调用的成员、引用、指针或切片带出该调用链，存入更长寿命的对象或作为后续独立调用的输入。禁止用 `swap`/`swapStorage` 转交工作区容器的存储。
- 脏数据与初始化： 旧内容默认视为脏数据，可在本次使用前或上次返回前清理。空/零状态必须由构造和所有返回路径（含提前返回）维护；没有清理保证的区域，下次使用前覆盖或重置。函数负责建立有效范围和初态；完全覆盖写入无需清零。
- 容器与 STL： 容器扩容和 [vector::resize](../../code/core/datastructure/vector.h) 不保证初始化或重置已有元素；不得读取未经初始化或验证的旧值，也不要求每次清空整个工作区。除 `mss::vector` 外，使用其他 STL 须事先申报位置、用途、分配成本和生命周期并获明确同意；批准只适用于获批用途。
- 正确性与并发： 遵守清理约定时，相同显式输入使用新建或复用的 `Workspace` 必须得到相同结果。尺寸、容量和首地址不能证明旧内容有效、数据身份相同或集合完整。每个线程使用独立的 `Workspace`；需要并发或重入时，沿实际调用关系确认工作区是否共享。

### Config

`Config` 只保存调用方需要调整的参数，每项都必须在构造时明确提供；类型本身不设置固定默认值或默认实参。固定算法规则、版本号等程序信息不属于 `Config`，应放在实现或独立常量中。程序入口和测试可以显式选择常用取值；这不是 `Config` 自身的默认值。

- 配置作为只读参数传入。只有确实协调多个模块参数的上层边界才接收完整的上层 `Config`；只想用一个阈值时传具体值或该模块的配置。

## 嵌套类型与字段分类

- 尽可能减少在一个结构体中堆放过多内容。字段较多或存在清晰的职责分组时，积极使用嵌套类型分类；子组内仍有不同职责时继续嵌套。
- 类型和字段按直接所属的模块、阶段或数据集合归组，通过嵌套路径表达归属。拆分以实际职责为依据，不规定字段数量上限或嵌套层数。

## vectorPool 的使用

`vectorPool<T>` 用一个连续的 `mss::vector<T>` 存放多段同类型元素，`vectorPool<T>::vector` 只保存一段的 offset/count。它的用途主要分为以下几类：

| 用途 | 组织方式 | 示例 |
|---|---|---|
| 对象的变长内容 | 对象保存各段切片，实际内容按元素类型集中存储；多个对象可以共享所属池。 | `Structure::Shape` / `Instance`、`ShapeSolver` 的分布与赋值、模板匹配表。 |
| 增量记录 | 每次更新追加一段变化，`Delta` 或评分结果保存该段，供后续重放、逆序撤回或继续搜索。 | `ObservedBoard` / `Basic` / `Structure` 的变化记录、`JavaLite` 的数字结局记录。 |
| 树的子节点列表 | 节点本体集中存储，每个节点用同一池中的切片表示一组连续子节点，根列表也用切片表示。 | `AnytimeSearch::Pool::Node::child` 与 `Result::roots`。 |
| 临时分组与计算缓冲 | 一次调用或递归帧内拼接多组数据、系数或中间表，记录切片以独立访问各段；下次使用时重建内容并复用容量。 | 暴力求解的安全组、`PolyProductTree` 的系数、概率抽样的后缀多项式、DFS 观测的卷积缓冲。 |

- **存储归属：** 按数据有效期选择持有者。跨调用共享内容放在对应 `Pool`；结果独占的分段内容可以由结果自身持有，例如 `ShapeSolverType::Observed::values`；临时段放在 `Workspace` 或其递归层内，并遵守上文工作区契约。
- **分段布局：** 多个同类型的变长数据段共用生命周期时，优先用 `vectorPool<T>` 存元素，由所属对象保存切片；单独组织切片列表时使用 `vector<vectorPool<T>::vector>`。不要只为保持地址稳定而逐段分配，再用 `vector<T *>` 管理。复杂对象的同类型变长成员可以分别入池，对象保存对应切片；池内元素须满足 `mss::vector<T>` 的可平凡复制约束，复杂对象本身不能直接作为池元素。
- **追加与填充：** `push_back()` 在池尾建立空切片，`push_back(part, value)` 只向当前尾部切片追加。建立后续段之前，先完成当前段的长度分配；树结构先把一组直接子节点连续放好，再展开它们的后代。已知各段长度时可以先分配各段，再按下标填充，已分配段可以在有效范围内改写。直接用 `data.resize()` 划分缓冲时，同步建立正确的 offset/count，初始化规则见上文「结构体与初始化」。
- **切片与指针：** 切片必须配合所属池读取，池扩容不改 offset/count，但会使旧的元素指针、引用及基于它们的视图失效。跨追加操作保留切片或下标，追加完成后再从池中取得所需地址。把某个段转存到另一个池时，复制实际元素并建立目标池切片。段内另存的 begin/offset 要注明相对本段还是整个池。
- **回退与清空：** `pop_back(part)` 把池长度退到 `part.offset`，截断该段及其后的内容；它只回退存储，状态撤回由算法完成。增量记录在撤回消费完之后再退池；去重命中时可以丢弃本次新建的尾段。只保留仍有效的切片，池清空或销毁后不再使用旧切片。临时分组跨递归调用仍需读取时，使用各深度独立的存储，避免下层重建覆盖上层数据。

## 文件组织与依赖方向

- 新增或修改必须服从 `code` 的既有文件组织；不因为“通常应该有 .cpp”就移动代码或拆文件。对本来以头文件组织的模块，按相邻模块风格做最小改动；不得把“整理文件”当成擅自扩大任务的理由。
- 一个统一入口下有多个算法后端时，采用 `XXX_type.h → (XXX_algoA.h / XXX_algoB.h) → XXX.h` 的组织顺序：共享类型定义在 `XXX_type.h`，后端包含共享定义并直接使用同一种结果类型，对外入口 `XXX.h` 汇总后端、公开类型并提供统一调用入口。公共配置可独立放在 `XXX_config.h`，供实际需要的层直接包含。
- 上述箭头表示从共享定义、后端到对外入口的组织顺序；include 依赖由入口指向后端、由后端指向共享定义。后端不反向包含对外入口，共享定义不依赖后端；入口可用 `using` 公开共享类型。
- 遵循同名头/源文件模式的模块，头文件放公开类型、契约和声明，非模板实现放同名 `.cpp`；模板定义和确实必须在头文件的实现留在头文件。`.cpp` 先包含自己的头文件，再包含实现依赖。
- API 注释写可执行的前置条件、对象所有权、引用或视图有效期以及并发限制。每条约束要能从实现核实。
