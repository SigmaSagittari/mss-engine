# 实现代码 Prompt

范围：只适用于 `code/`。

前置：必读清单见 `AGENTS.md`（`../../AGENTS.md`），规则归属见 `docs/README.md`（`../README.md`）。

不在这里重复：C++ 写法、结构体初始化、算法模块五类结构、工作区与池的契约、文件组织，统一见 `style.md`。

## 可靠性与性能

### 诊断与终止

- 显式异常退出，只允许用项目 `core/assert.h`（`code/core/assert.h`）里的 `assert_(false, "中文错误信息")`。
- 条件断言，只允许用 `assert_(条件, "中文错误信息")`。
- 可继续执行的内部告警，只允许用 `warn_("中文告警信息")`。
- 不可达分支不得返回默认对象或其他兜底结果。
- 热路径不增加断言。

以下方式一律禁止，因为它们绕过了项目诊断：

- 标准 `assert`；
- 直接调用 `exit` / `std::exit`，包括 `exit(1)`；
- `abort`、`terminate` 或其他终止函数；
- 用异常路径上的非零返回码代替上述异常退出。

唯一实现例外：`core/assert.h` 对底层终止操作的封装。这个例外只属于该头文件内部，调用方不得仿效。

### 数据结构

- `core/utility` 提供一组高性能库，例如位掩码、`flat_hashtable`。
- 引入 map 时，先考虑能不能规避。
- 确实无法规避，才用哈希表。

### 代码风格取向

- 绝对禁止任何防御性编程。

## 领域与接口职责

- 引擎 API 直接传实际状态、结果、池和必要参数，不包一层重复的 DTO。
- 工作区在模块内部取用，契约见 `style.md`。
- 不解析 UI 文本或 HTTP 字段。
- 不反向依赖主 `Config`。
- 直接使用项目已有的领域类型和调用入口。
- 不要复制棋盘规则、概率状态、缓存或资源所有权来绕开 API。

## UI、JavaScript、HTML 与 CSS

- 改动浏览器代码前，先读任务涉及的相邻函数、数据流和 DOM 定义。
- 只改本次要求的行为，沿用当前的 DOM、请求和状态管理方式。
- 不在浏览器端复制 Game 或引擎已经拥有的规则。
- 若 Game 还没有相应的公开动作 API，先指出这个具体缺口，不要自己绕过去。
- 修改请求字段时，同时追踪五段链路：前端编码 → HTTP 接收 → Session 解析 → 领域 API → 响应渲染。
