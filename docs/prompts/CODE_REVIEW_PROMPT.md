# mss0.16 编码与审查 Prompt

本文件适用于 [code](../../code/)。范围、优先级、必读清单和授权见 [AGENTS.md](../../AGENTS.md)，规则归属见 [docs/README.md](../README.md)。本文件只管怎么动手、怎么判断、怎么报告，不重复其他文档的条款。

## 修改前

- 修改前检查工作树、分支和本次 diff，不覆盖、不重置、不混入无关文件。
- 只处理用户要求的范围和由此必需的改动。用户只要求审查时，只审查本次 diff 或指定范围；查看未改动代码只为确认依赖、定义和调用，不把旧问题混进本次意见。
- 不添加胶水层、重复规则、镜像状态、额外 facade 或只转发参数的包装。现有 API 确实无法完成任务时，说明缺少的 API、调用者和最小职责，先取得批准。
- 不主动设计“更好的架构”或把目标扩成重构。用户明确要求架构方案时，方案要落到真实文件和 API，并明确它只是方案；实现仍需授权。

## 仅审查

- 每条意见给出文件与行、可复现条件、实际影响和最小修复方向。区分源码已证实事实与推断；没有证据就继续查，不写空话。
- 报告用中文按严重程度排序；没有可证实问题时明确写“未发现可证实的问题”，并列出检查范围和未执行的验证。

## 可靠性判断

- 信任已经测过的组件。禁止为了“更稳健”重复验证 API 已保证的条件、添加兜底结果、吞掉错误、静默回退或继续在无效状态运行。
- 遇到意外、矛盾或奇怪的结果，先追查并按 Bug 处理；不能先编造牵强原因解释掉异常。
- 不得返回默认值、空结果或其他假成功结果；不得把内部致命错误伪装成业务返回。
- 性能回退也是 Bug。用实际输入和完整调用路径定位；没有测量的数据只能标为假设，不能写成结论。
- 确认不是 Bug 时，在相关代码处用中文注释说明依据；必须读函数实现才能解释本次行为时，也留最小必要中文说明。注释不得扩散到无关代码。
- `assert_`、`warn_` 和禁止的终止方式按 [implementation.md](implementation.md)。

## 风格与审查方法

- 严格贴合相邻实现的命名、格式、文件边界和已有 API；相邻实现只作为风格证据，不能覆盖 [implementation.md](implementation.md) 的明确禁令。
- 遵守 anti-童子军规则：不顺手清理、不重排、不统一未要求的旧代码。默认不增加无关行；新增行数必须由功能需要证明，即便新增功能，也应当尽可能保持精简。
- 按 [implementation.md](implementation.md) 逐条检查本次 diff 的禁用写法、结构体默认值、`Config`/`Workspace` 归属和接口参数。
- 审查每个疑点时追到类型定义、函数定义、调用点及关联状态。职责边界按 API 的定义模块判断，不能把“谁调用了它”误当成“它属于谁”。

## 工具与回复

- 构建、测试和 benchmark 按 [operations.md](operations.md) 执行。
- 用中文回答。数学内容使用 LaTeX，不放进代码块。用直白、具体的中文表达，少用套话、空泛评价和模型常见填充词。
- 用户只要数据时，用表格给出实际取得的数据；只有严重妨碍阅读时才压缩。
- 直接说明要做或已做的动作及证据；说明取舍时只写会影响决策的方面，省去已知的平衡句。
- 报告改了什么、为什么、验证了什么；只说实际执行过的验证，不暗示未运行的测试通过。

## 未完成工作

- 每次回复前核对用户要求是否全部完成。若还有跨轮未完成的明确目标，创建或更新长期 goal 并继续推进；不能把部分完成说成完成。用户明确暂停时才暂停。
- 需要用户手动执行安全操作才能继续时（例如结束阻塞进程），直接说明具体操作和阻塞影响；不要静默停住。
