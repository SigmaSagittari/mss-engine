# 测试 Prompt

范围：只适用于本仓库的测试。

前置：必读清单见 `AGENTS.md`（`../../AGENTS.md`），规则归属见 `docs/README.md`（`../README.md`）。

- 不要自行复制旧的 harness、注册器或夹具框架。
- 测试树尚未落地时，新增测试前先向用户确认入口、目录和构建方式。

## 盘面来源与正确性判定

### 盘面从哪来

- 优先用这三种来源：固定种子的随机对局、真实运行记录、已发现的失败样本。
- 尽量不要由测试作者手工构造盘面。
- 例外：用户提供或明确要求的构造盘面，可以直接保留。
- 需要固定回归时，优先把上述来源的盘面与操作序列固化下来。

### 怎么判对错

- 正确性测试围绕 API 契约和实际结果设计。
- 优先用生成式差分或性质检验。
- 具体走法：从实际生成的盘面、候选集合和操作结果出发，按契约系统地派生后续合法输入和调用序列，再核对结果。
- 判定依据必须有独立来源，例如小规模完整枚举、可信参考实现，或可证明的不变量。
- 核对的是契约相关的完整语义结果和状态变化，不只是比对返回值。
- 优化前后比较，只用于验证行为有没有改变，不能替代上面的独立判定依据。

### 失败时留什么

失败时要留下四样，让失败可以重放、并能固化成回归：

- 生成种子；
- 盘面；
- 操作序列；
- 预期结果与实际结果的差异。

## 随机多局测试

### 两个上限

- 对局数上限和目标时长都是有限的正数。
- 测试驱动同时受两者约束，先到先停。

### 先到的是哪一个

- 目标若是完成 `maxGames` 局：必须确认实际完成数等于目标。
- 目标若是测固定时长吞吐：`seconds` 是测量目标，`maxGames` 是保护上限。

对应地：

- 时限先到 → 报告用例未完成；
- 游戏数先到 → 说明测量被上限截断。

### 输出

- 固定随机种子，保证同样的测试设置可以复现。
- 输出九项：测试名、盘面尺寸和雷数、种子、目标时长、目标对局数、实际对局数、胜负、实际耗时，以及本用例需要的统计。
- 摘要对象里保存实际测得的统计，不要填估计值。
- 测试前置条件要保证百分比、均值和吞吐量的分母非零。
- 外部硬超时按 `operations.md` 设置。

## 固定盘面和引擎回归

- 固定盘面类测试，把六项集中定义在对应测试用例内：固定盘面、种子、预期布局数、预期胜局数、操作顺序、断言。
- 概率增量 API 的专门回归，可以直接调用被测模块，检查三者之一（或组合）：合法候选数、状态一致性、用户指定的不变量。
- BruteForce 单线程 / 多线程比较：从当前公开 API 设置求解选项，检查同一固定盘面上的明确结果，不要用内部入口。
- 需要 Game 行为时，先读 `GameControl::Game` 的实际声明，用现有 API。缺所需行为时，明确报告 API 缺口。
- 关注点分工：
  - 固定概率盘面 → 验证概率 / 增量接口；
  - 固定残局 → 验证枚举和结果；
  - 随机对局 → 统计实战行为。

## 测试自己的配置

- 运行设置、测试目标、测试上限属于测试层，不要混进生产配置。
- 使用测试自己的配置类型，例如 `test::Config`，或用户明确指定的测试层类型。
- 需要统一随机完整对局参数时，测试配置集中保存：盘面行数、列数、雷数、目标时长、最大对局数，以及确实被多个这类用例共同使用的测试模式。
- 每个用例只构造一个配置值。
- 生产配置按被测 API 的签名提供，不要为测试改造签名。
- 具体引擎参数只放在确实测试该参数的用例设置里。
- `BruteForce::Config` 属于 `BruteForce` 模块，按生产 API 传给 `BruteForce::solve`，不要另建测试专用配置。
- 工作区由模块内部取用，遵循 `style.md` 的 Workspace 约定。

## 用例入口与文件

- 新用例沿用用户指定的测试入口和相邻文件的风格。
- 不新增第二套入口、命令行注册器、插件表或生产入口开关——除非用户明确要求。
- 公共文件只放多个测试确实共用的类型和驱动。
- 以下四类留在用例内部，不要上提到公共文件：用例数据、局部 lambda、期望值、只被一个用例调用的步骤。
- 不要为了"统一架构"擅自做跨文件架构更改，包括：
  - 把本来以头文件组织的测试拆成 `.cpp`；
  - 创建胶水层；
  - 创建 fixture 框架；
  - 创建通用注册系统。

  这类更改必须按总 Prompt 取得授权。
- 测试的名字、seed、输入、断言和输出，应当能让失败复现。

## 运行

- 运行方式、硬超时、benchmark 按 `operations.md`。
- 本文件只加一条：报告里要带上用例的实际输出。
